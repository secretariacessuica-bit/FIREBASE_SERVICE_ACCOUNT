## 📚 Documentação Oficial
Todas as regras, rotas de arquitetura, tarefas pendentes e histórico de evolução estão mantidos no diretório `docs/`. É estritamente proibido iniciar qualquer alteração no código fonte sem o conhecimento desta documentação.

### 📌 Ordem Obrigatória de Leitura (Onboarding)
Se você é um novo desenvolvedor no projeto, siga a ordem de leitura abaixo antes de escrever a sua primeira linha de código:

1. **[ARQUITETURA.md](docs/ARQUITETURA.md)**: Compreenda a visão geral, como os módulos se comunicam, a topologia do Firebase e os Domínios Funcionais do sistema.
2. **[CODING_STANDARD.md](docs/CODING_STANDARD.md)**: Estude a Constituição do projeto. Aqui estão os padrões inegociáveis de escrita de CSS, extração de Funções UI e as práticas rigorosamente proibidas.
3. **[ROADMAP_V1.md](docs/ROADMAP_V1.md)**: Entenda de onde viemos (Legado), onde estamos (Componentização) e para onde vamos (Multi-Instância White Label).
4. **[BACKLOG.md](docs/BACKLOG.md)**: Descubra quais são as tarefas estruturais e refatorações que estão abertas e mapeadas para a Sprint atual.
5. **[CHANGELOG.md](docs/CHANGELOG.md)**: Fique por dentro de tudo o que aconteceu tecnicamente até a data de hoje.
